Glue errors found and fixed (minimal edits; originals in scratchpad r1b/integ_orig)
1. K -> R, J-lens index convention (r1b_r_s5.py, r51_block and rg10). MOCK K4j (r1b_K_S1, k4j.json) chose the 'input' convention.
   Under it, block 26's output needs J[27], which the 27-map stack does not have, so s5_r51_b26 raised NotRun and, through the step
   chain (after=), RG10, RG11, R5.2 and R5.3 of r1b_R_S5 were all 'not run' (the same would happen on the GPU whenever K4j picks
   'input'). R's self-test only plants 'output'. Fix: R5.1 writes r5/r51_b26.json as a coded record (not_run
   NA:not_run:no J-lens map for block 26 under convention input) instead of raising; RG10 reads a record without directions as
   valid=False with that code (RG10 already did this for a missing file), so RG11's rule (refit if not valid at 14 or at all of
   22, 24, 26) still applies. In MOCK the runner had hidden this by mock-filling jlens_validity.json / rg11.json; r1b_R_S5L then
   failed (KeyError 'blocks' in _valid).
2. Same cause, R5.2 (r1b_r_s5.py, r52): the block loop crashed on J = None (AttributeError) once RG10 ran. Fix: block 26 without
   a map gets a coded entry (string NA:not_run:...) and is skipped. r1b_R_S5, r1b_R_S5L and r1b_R_ana were reset and rerun.
3. K -> L, K4 gating answers (r1b_l_ana.py, l5a). k4_gating.json (r1b_K_S2a) stores greedy and samples as generated token ids
   (also on the GPU path, r1b_k_s2.py); L-ANA's L5a parsed them as text (TypeError in re.findall), so l_ana and the round-level
   steps of r1b_ana failed. Fix: L5a decodes token-id answers with the tokenizer (skip_special_tokens) before reading numbers.
